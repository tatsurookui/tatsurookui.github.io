# Tatsuro Okui — Personal Portfolio

A static Jekyll site for GitHub Pages. All pages are written in Markdown with YAML front matter; shared HTML lives in Jekyll layouts and includes, and styling is plain CSS.

## Publish with GitHub Pages

1. Create a GitHub repository named `tatsurookui.github.io`.
2. Put this site's files at the repository root and push them to the `main` branch.
3. In the repository, open **Settings → Pages**.
4. Set the source to **Deploy from a branch**, select **main** and **/(root)**, then save.
5. After GitHub Pages finishes building, visit `https://tatsurookui.github.io`.

This is a GitHub user site, so `_config.yml` intentionally sets `baseurl` to an empty string. The site uses GitHub Pages' standard Jekyll build; no separate build workflow or backend is required.

## Update the site

- Edit `index.md`, `about.md`, `work-experience.md`, and `contact.md` to update page content.
- Keep the YAML front matter at the top of each page. It controls the page title, description, URL, and navigation order.
- Add shared page structure in `_layouts/` or `_includes/`.
- Edit `assets/css/main.css` for visual changes.
- Update `_config.yml` if the site title, description, or canonical URL changes.
- Keep navigation destinations and the sitemap current when adding pages.
- Replace bracketed `[Placeholder: …]` copy only with information you choose to provide. Do not add unverified biography, employers, achievements, or metrics.
- This site intentionally does not publish an email address or `mailto` link.

## Preview locally

In Replit, run the **Jekyll Preview** workflow. It uses Jekyll's built-in development preview on port 5000—not Vite, a framework application, or a separate server implementation. GitHub Pages still publishes the static site from the repository root.

Install Ruby and Bundler, then run from the repository root:

```sh
bundle install
bundle exec jekyll serve
```

Open `http://localhost:4000`. Jekyll rebuilds the site when files change. Use `Ctrl+C` to stop the preview server.

## Run Lighthouse

After publishing, open `https://tatsurookui.github.io` in Chrome:

1. Open Chrome DevTools.
2. Select **Lighthouse**.
3. Run an audit for **Performance**, **Accessibility**, **Best Practices**, and **SEO**. Run both desktop and mobile audits to check responsive behavior.
4. Review any recommendations and rerun the audit after changes.

Lighthouse results depend on the browser and audit environment. This site avoids external fonts, image dependencies, trackers, and client-side libraries to keep its page weight and requests low.

## Technical choices

- Custom Jekyll layouts and includes keep page content separate from presentation.
- `relative_url` is used for internal links and assets; `absolute_url` is used for canonical URLs and the sitemap.
- SEO metadata is generated by a small local include. `sitemap.xml` and `robots.txt` are generated from the site URL without an external plugin.
- System font fallbacks avoid third-party font requests.
- The site uses semantic HTML, a keyboard skip link, visible focus styles, responsive CSS, and reduced-motion support.
- There is no backend, database, form service, blog, CMS, analytics tracker, or public email link.
